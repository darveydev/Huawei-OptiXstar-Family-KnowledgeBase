# 华为 OptiXstar FTTR 全桥接改造 + 公网 DDNS 出口 — 结论速览

> 适用设备：主网关 OptiXstar V176-20（XGPON）× 1，从光网关 OptiXstar K156-20（GPON）× 3
> 拨号路由：GL.iNet GL-MT6000（Flint 2，OpenWrt 系，双 2.5G 口）
> 文档目录：`E:\OwnFiles\Huawei-OptiXstar-Family\`

## 一句话结论

| 你问的问题 | 答案 | 风险 |
|---|---|---|
| 能不能把**所有**光网关都改桥接？ | **不建议，且做不到字面意义**。能做的是"只有主网关桥接"，三个 K156-20 天生就是桥接从机 | — |
| 主网关桥接 + K156-20 继续用光纤组网 + MT6000 拨号，可行吗？ | **可行**，但需要 VLAN 手法（本文第 3 章），不是改个开关就行 | 中 |
| 能不能直接全部桥接让 MT6000 拨号？ | **纯全桥接会让 3 个 K156-20 变成砖**（无 Wi-Fi、无网口），必须走 VLAN 方案或放弃从网关 | 高 |
| 移动给了动态公网 IPv4 后能不能做 DDNS 出口？ | **能**（前提是真公网 IP，见第 5 章鉴别法）。但**移动大概率不给**，我更推荐 IPv6 或异地组网兜底 | 中 |

**推荐路径（不走弯路版）：**
```
V176-20 桥接（保留 FTTR 光口下发）
   ↓ 一条网线（可选单线复用 VLAN）
GL-MT6000 PPPoE 拨号 + DHCP + DDNS
   ↓ 网线回灌主网关 LAN 口
V176-20 的 Wi-Fi + 3× K156-20 光纤从网关 全部变 AP
```
这条路径**保住全屋光纤覆盖**、**让 MT6000 掌握网关权**、**公网映射只需要在 MT6000 上做一次**。

## 先做这一步：确认你到底有没有公网 IP

⚠️ 这是整件事的**分水岭**。没有公网 IPv4，第 6 章之后的 DDNS 全部无效。

```bash
# 1) 在光猫/路由器后台看 WAN 口拿到的 IP
# 2) 用手机流量（断开Wi-Fi）访问 https://myip.ipip.net 看出口 IP
# 3) 两个 IP 完全一致 = 真公网；不一致 / WAN口是 10.x / 100.64.x~100.127.x / 172.16~31.x = CGNAT 内网
```

判定表：

| WAN 口 IP | 出口 IP | 结论 |
|---|---|---|
| 112.38.x.x | 112.38.x.x | ✅ 真公网动态 IP，可直接 DDNS |
| 112.38.x.x | 另一个 112.38.x.x | ⚠️ 双栈 NAT / 池化，端口映射可能失效 |
| 10.x / 100.64~127.x / 172.16~31.x | 112.38.x.x | ❌ CGNAT，无法映射，只能 IPv6 或内网穿透 |

> 本机实测（2026-11-15，直连不走代理）：出口 `112.38.217.15`，归属山东济南移动。
> 这个 IP 落在移动固网地址池里，**看起来像公网**，但仍必须在光猫后台核对 WAN 口 IP 才能定性。
> 注意：本机有 Tailscale 在跑（`fd7a:115c:a1e0::` 地址段），测试时请**先退掉**，否则测到的是 Tailscale 出口。

## 三条铁律（违反必翻车）

1. **改桥接前必须先拿到宽带账号密码 + VLAN ID。** 桥接后光猫不再拨号，你丢了账号就只能报修。VLAN ID 移动常见 41，但**必须从原配置里抄下来**，不能猜。
2. **改之前把原配置每一页拍照。** 特别是"网络 → 宽带设置"整页、"LAN 口多业务"页、"安全"页。
3. **永远保留一条退路**：改之前准备一根网线 + 一台能拨号的设备（笔记本也行），并且知道光猫复位孔位置。桥接配错了，插网线直连光猫拨号可以立刻验证账号是否有效。
