# 技术勘误与实施前核验

本文对原始压缩包做技术审阅。目标不是把所有不确定内容替换成另一套猜测，而是区分**可由官方资料确认的事实、现场必须核验的参数、原文中不应直接执行的指令**。

## 1. 已识别的高优先级问题

| 原资料表述/做法 | 问题 | 修订原则 |
|---|---|---|
| VLAN ID 固定写为 41 | 不能跨省份、OLT、套餐通用 | 全部改为“示例值”；从原 WAN 配置/运营商工单读取实际 VLAN ID |
| K156-20“出厂就是桥接”“不能单独上网” | 不能仅凭型号/界面模式推断运营商业务模板和 FTTR 承载方式 | 以设备铭牌、管理页面、光路拓扑、业务 VLAN 和装维配置核验 |
| 主网关桥接后就能当普通二层交换机，FTTR 从机自然继续工作 | FTTR 主从管理/承载可能依赖专有 VLAN、控制通道和端口绑定；普通 LAN VLAN 不一定等价于 FTTR 业务 | 未验证 FTTR 光口业务承载前，不执行桥接切换 |
| “纯全桥接会让从网关变砖” | 结论过于绝对；可能失去业务，也可能在特定配置下保留部分服务 | 改为“可能导致从网关失联/业务中断，必须以实际业务映射验证” |
| MT6000 第二个 2.5G 口必须切成 LAN | 该口是 WAN/LAN 可切换口；只有采用回灌设计时才需要配置为 LAN | 仅在方案需要时切换；核对当前固件界面和接口状态 |
| MT6000 端口可按 eth0/eth1 固定映射 | Linux 逻辑设备名与物理端口映射受固件/交换芯片/DSA 配置影响 | 用后台端口页、`ip -br link`、`ubus call system board`、`uci show network` 核实 |
| 用 `grep` 结果判断 PPPoE WAN IP 一定是公网 IPv4 | 可能漏掉 IPv6、多个地址、NAT 或输出格式差异 | 用 `ifstatus wan`/LuCI 完整状态核验，并同地址族对照外部 IP |
| WAN IP 与 `myip` 不同就一定 CGNAT | 也可能是 IPv4/IPv6 地址族不一致、上游多级 NAT、代理/VPN 或出口检测方式差异 | 先强制同地址族检测（如 `curl -4`），再结合 WAN 地址段判断 |
| “移动 95%+ 强制 CGNAT”等精确比例 | 原文没有可靠统计来源 | 删除确定比例，改为地区/套餐差异，实际查询运营商 |
| K156-20 必须蓝灯常亮 | 指示灯定义可能随型号/固件/运营商定制变化 | 查对应设备说明书和现场状态页，不把颜色作为唯一验收条件 |
| 关闭 TR-069 可防止配置被覆盖 | 可能影响运营商远程维护、业务下发、注册或报修 | 不建议未经运营商确认关闭；先记录配置并确认是否有 ACS 策略 |
| `uci set firewall.@zone[1]...` 等按索引修改防火墙 | zone 顺序不保证固定，可能改错对象 | 先 `uci show firewall`，按 `name`/实际 section 核验；改后检查完整配置 |
| 将 SSH 端口映射到公网并关闭密码登录即可安全 | 仍然扩大攻击面；端口变更不等于安全 | 默认不开放管理端口；优先 Tailscale/WireGuard；必须暴露时做源地址限制、密钥认证和日志监控 |
| IPv6 入站只放行端口即可 | IPv6 通常无 NAT 隔离，防火墙规则/源区域/目标地址范围必须准确 | 逐项验证防火墙策略；不要对整个 LAN 做宽泛放行 |
| “端口转发按域名无所谓” | DNAT 通常匹配目的 IP/端口，不是自动按域名匹配；DDNS 只负责解析 | 明确 DNS、端口转发、服务监听、回程路由和防火墙各自职责 |

## 2. 设备型号与硬件核验

### GL.iNet GL-MT6000
官方规格显示：
- 1 × 2.5G WAN；
- 1 × 2.5G WAN/LAN；
- 4 × 1G LAN；
- DDR4 1GB / eMMC 8GB。

参考：
- https://docs.gl-inet.cn/router/4/resources/specification/gl_mt6000_spec/
- https://www.gl-inet.com/products/gl-mt6000

因此原文“第二个 2.5G WAN/LAN 口可切 LAN”这一硬件能力本身有依据，但具体操作页面和底层端口映射必须以设备固件版本为准。

### 华为 FTTR 设备
华为 iFTTR 公开资料列出 V176-20 与 K156-20 的接口规格示例，但运营商定制版本、硬件批次、固件和业务模板可能不同。公开产品彩页不能证明某台设备的所有 VLAN/端口绑定/桥接行为。
参考：

## 3. 实施前必须收集的现场参数

- [ ] 主、从光网关完整型号（铭牌照片脱敏）
- [ ] V176-20 软件版本/硬件版本/运营商定制版本
- [ ] K156-20 软件版本与当前注册状态
- [ ] FTTR 物理拓扑：主网关下行光口、分光器、各从网关连接关系
- [ ] 当前所有 WAN 连接：业务类型、连接模式、VLAN ID、802.1p、端口/SSID/FTTR 绑定
- [ ] PPPoE 账号与密码（只本地保管，不提交仓库）
- [ ] MT6000 固件版本、接口角色、LAN 网段
- [ ] 可用网线数量、每条线两端位置
- [ ] 当前是否存在 IPTV、语音、远程管理、家庭存储等其他业务

## 4. 推荐的实施决策顺序

1. **优先验证双线回灌可行性**：一条链路承载桥接 WAN，另一条链路承载 MT6000 LAN 回到 FTTR 主网关 LAN/合适业务口。具体端口是否可用由 V176-20 业务绑定决定。
2. **单线 VLAN 复用作为进阶方案**：必须同时掌握运营商 WAN VLAN、家庭 LAN VLAN、PVID、tagged/untagged 和 FTTR 下行承载关系；不清楚任何一项就停止。
3. **无法确认 FTTR 保留方案时采用旁路由/现有路由模式**：先保障全屋联网，不为“主路由接管”牺牲整套 FTTR。
4. 每次只改一个变量；每步验证 WAN、LAN、从网关在线状态和管理可达性。
5. 改造完成后跑验收清单，保留配置备份和回滚路径。

## 5. 高风险命令使用规则

- 执行前保存 `uci export` 和 GL.iNet 后台备份。
- 不复制其他设备的 `@zone[1]`、`@rule[-1]` 等索引命令，先检查当前 section。
- 不在未确认 VLAN/接口名称时执行 `uci commit network` 后重启网络。
- 不在仅有远程管理链路时修改 WAN、LAN 地址、VLAN、默认路由或防火墙。
- 不建议直接恢复出厂；FTTR 光网关可能需要运营商重新注册/下发配置。
- 不提交真实密码、Token、序列号、MAC、公网 IP 或完整未脱敏配置。

## 6. 仍待现场验证的事项

以下项目不应在知识库中写成已验证结论：
- V176-20 桥接后是否仍可通过指定端口/业务 VLAN 保持 FTTR 主从管理和数据转发。
- K156-20 的具体工作模式、管理通道、上网业务 VLAN 与从机注册行为。
- VLAN 单线复用是否受该运营商固件的 VLAN 绑定能力限制。
- 光猫网口 1/3/4 与 FTTR 下行光口能否按设想承载同一 LAN。
- 移动宽带所在地区是否提供公网 IPv4、IPv6 入站是否可达。
